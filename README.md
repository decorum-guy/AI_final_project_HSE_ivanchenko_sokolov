# ИнфоПульс

**Финальный проект по дисциплине:** «Автоматизация коммуникационных процессов с помощью искусственного интеллекта»

**Выполнили:** Иванченко Артем Сергеевич и Соколов Егор Алексеевич  
**Группа:** БРО2301

Работающий бот текущей версии репозитория доступен в Telegram: [@everyone_needs_a_digest_bot](https://t.me/everyone_needs_a_digest_bot)

---

## Описание проекта

**ИнфоПульс** — Telegram-бот для персональных новостных дайджестов из RSS-источников.

Бот собирает материалы из выбранных RSS-лент, помогает пользователю указать интересы, подобрать источники, сформировать краткий дайджест с помощью ИИ и сохранить историю ранее созданных подборок.

Проект ориентирован на автоматизацию коммуникационного процесса: пользователь не просматривает десятки сайтов вручную, а получает сжатую, структурированную и персонализированную новостную сводку в Telegram.

Важно: проект использует доступные учебные ресурсы и бесплатный/бюджетный режим работы с ИИ. Качество форматирования, отбора материалов и фактическая точность могут зависеть от выбранного LLM-провайдера и модели. Генеративная модель может ошибиться в фактах, акцентах, структуре или HTML-разметке. В проекте добавлены проверки, постобработка, fallback-сценарии, лимиты и защита от слишком длинных сообщений Telegram, но стопроцентно идеальный контроль содержимого невозможен.

## Что умеет бот

- Собирает дайджест из выбранных RSS-лент.
- Поддерживает два режима чтения:
  - `📡 По источникам` — дайджест из выбранных RSS-лент.
  - `🎯 По интересам` — дайджест из выбранных RSS-лент, но с сортировкой по вашим темам.
- Помогает указать интересы и подобрать RSS-источники через ИИ.
- Нормализует интересы в 2-8 ключевых тем для более точной персонализации.
- Позволяет вручную редактировать нормализованные слова интересов.
- Позволяет очистить интересы с подтверждением: удаляются и свободный текст, и нормализованные слова.
- Позволяет вручную исключать отдельные источники из ИИ-рекомендаций перед добавлением.
- Поддерживает ручной выбор источников через категории.
- В разделах `⭐ Подписки` и `📡 Источники` есть действие `🧹 Очистить все`: оно снимает только пользовательский выбор источников, не удаляет RSS-источники из проекта и не меняет `sources.xlsx`.
- В ИИ-рекомендациях исключенные пользователем источники визуально зачеркиваются, а пометка `(Удалено пользователем)` остается рядом с названием и не зачеркивается.
- Показывает выбранные источники через `✅` и `☐`.
- Формирует Telegram-дайджест в HTML-совместимом формате.
- Сохраняет историю дайджестов.
- Позволяет добавлять дайджесты в избранное.
- Принимает оценку дайджеста: `👍 Полезно` / `👎 Не подходит`.
- Позволяет проверить новые новости после генерации дайджеста.
- Поддерживает плановые рассылки:
  - каждое утро;
  - каждый вечер;
  - раз в неделю.
- Позволяет выбрать часовой пояс через город и UTC-смещение.
- Поддерживает уведомления без звука.
- Работает с `GigaChat` и `ChatGPT` как с LLM-провайдерами.
- Имеет админ-панель.
- Имеет watchdog-скрипт для запуска и мониторинга бота на VPS.
- Для больших дайджестов создает HTML-страницу и умеет отправлять дайджест частями.

## Единый onboarding и главное меню

Во всех сценариях главное меню показывает один и тот же текст:

```text
👋 ИнфоПульс помогает собрать короткий новостной дайджест из RSS-источников.

Можно читать новости двумя способами:

`📡 По источникам` — дайджест из выбранных RSS-лент.
`🎯 По интересам` — дайджест из выбранных RSS-лент, но с сортировкой по вашим темам.

Как получить дайджест:
1. Добавьте или измените интересы.
2. Подберите или измените источники через ИИ или вручную.
3. Нажмите «Получить дайджест».
4. Выберите режим и период.

Интересы не заменяют источники: они помогают точнее отсортировать новости внутри выбранных лент.
```

Этот текст используется в `/start`, при возврате в меню через callback и после оценки дайджеста. Это сделано, чтобы пользователь не видел сухое сообщение `Главное меню` и всегда понимал следующий шаг.

## Логика работы бота

Полная карта пользовательской навигации вынесена в [BOT_FLOW.md](BOT_FLOW.md). В README зафиксирована основная логика пользовательских сценариев, а в BOT_FLOW.md подробно описаны экраны, кнопки и переходы.

### Получение дайджеста

Сценарий начинается из главного меню по кнопке:

```text
📰 Получить дайджест
```

После этого бот предлагает выбрать основу дайджеста:

```text
🎯 По интересам
📡 По источникам
```

На экране выбора режима показывается короткое объяснение:

```text
Как сформировать дайджест?

📡 По источникам — дайджест из выбранных RSS-лент.

🎯 По интересам — дайджест из выбранных RSS-лент, но с сортировкой по вашим темам.
```

Важно: интересы не заменяют источники. В обоих режимах бот работает с уже выбранными RSS-лентами; режим `🎯 По интересам` дополнительно сортирует новости по сохраненным темам пользователя.

Затем пользователь выбирает период:

```text
За сегодня
За последние 3 дня
За неделю
```

После выбора периода бот собирает новости из RSS-источников, формирует Telegram-дайджест и автоматически сохраняет его в историю.

## Как выглядит Telegram-дайджест

Telegram-дайджест формируется только в HTML-совместимом формате:

```html
<b>📰 Дайджест за сегодня (22.05.2026)</b>

<b>Очень кратко</b>
<blockquote>Главные события дня в мире финансов и технологий. Не более двух предложений.</blockquote>

<b>Подробно</b>

<b>1. Заголовок новости</b>
<b>Кратко:</b> ...
<b>Почему важно:</b> ...
Источник: <a href="URL">Название источника</a>

<b>Итог</b>
<blockquote>Короткий вывод.</blockquote>
```

Особенности текущего формата:

- слоган полностью убран;
- заголовок `Новости` заменен на `Подробно`;
- блок `Очень кратко` оформляется через цитату;
- подписи `Кратко:` и `Почему важно:` выделяются жирным;
- ссылки на источники оформляются как кликабельные HTML-ссылки;
- Markdown в итоговом Telegram-сообщении не используется.

## Интересы и ИИ-подбор источников

ИИ-подбор источников запускается из раздела `🎯 Мои интересы`.

Пользователь пишет интересы обычным текстом, например:

```text
люблю технологии, игры и театр
```

После этого бот может:

1. сохранить интересы обычным текстом;
2. показать промежуточное сообщение `🤖 Анализирую интересы и выделяю ключевые темы...`;
3. нормализовать интересы в 2-8 ключевых тем;
4. предложить RSS-источники на основе интересов пользователя;
5. дать пользователю вручную отредактировать нормализованные слова.

При ручном удалении нормализованных слов бот остается на экране удаления: можно нажать несколько слов подряд, а затем вручную вернуться назад.

Нормализация интересов выполняется отдельным коротким запросом к ChatGPT `gpt-5.4-nano`: модель убирает служебные слова вроде `люблю` или `нравится`, приводит темы к начальной форме и не должна добавлять дальние ассоциации. Если ИИ недоступен или вернул невалидный JSON, бот использует fallback по ключевым словам.

При подборе источников бот читает активные источники из `sources.xlsx` и передает модели список доступных RSS-источников: `source_id`, название, категорию и описание. Модель должна выбирать только источники из этого списка. Если ИИ недоступен или возвращает некорректный JSON, бот использует fallback-подбор по ключевым словам.

Важно: ИИ-подбор источников не генерирует сам дайджест. Он только помогает сформировать список подписок. Сам дайджест потом строится по уже выбранным источникам.

### Линейный flow “интересы → источники → дайджест”

После `Добавить все` в рекомендованных источниках бот больше не уводит пользователя просто в `Мои подписки`.

Теперь показывается экран:

```text
Источники добавлены. Теперь можно сформировать дайджест.
```

Кнопки:

```text
📰 Получить дайджест по интересам
📡 Изменить источники
🏠 Главное меню
```

Кнопка `📰 Получить дайджест по интересам` переводит пользователя к выбору периода для режима `interests`.

## Источники новостей

Источники хранятся в файле:

```text
app/data/sources.xlsx
```

В книге используются два листа:

- `Sheet1` — основной лист с RSS-источниками, который читает бот;
- `category_summary` — сводка с количеством источников по категориям для быстрой проверки наполнения.

Структура таблицы:

| Поле | Описание |
|---|---|
| `source_id` | уникальный идентификатор источника |
| `title` | название источника |
| `category` | категория источника |
| `description` | краткое описание |
| `rss_url` | ссылка на RSS-ленту |
| `is_active` | активен ли источник |

Пример строки:

| source_id | title | category | description | rss_url | is_active |
|---|---|---|---|---|---|
| `habr_articles` | Хабр | IT | Разработка, IT, технологии и инженерные статьи | `https://habr.com/ru/rss/articles/` | `true` |

Важно: файл `sources.xlsx` используется как основной список источников. Если файл уже существует, его не нужно пересоздавать или перезаписывать без необходимости.

В интерфейсе выбора источников бот показывает категории и источники внутри них. Состояние выбора отображается через:

```text
✅ — источник выбран
☐ — источник не выбран
```

Также бот показывает рекомендацию по объему: оптимально выбирать `3–7` источников. Если выбрано много источников, перед генерацией бот предупреждает, что дайджест может получиться длинным.

## Параметры отбора новостей перед ИИ

Перед отправкой материалов в ИИ бот ограничивает объем входных данных, чтобы не перегружать модель, не увеличивать стоимость запроса и не получать слишком длинный дайджест.

Текущие параметры:

- максимум источников на один дайджест: `12`;
- максимум статей с одного источника:
  - `today` — 3 статьи;
  - `3days` — 4 статьи;
  - `week` — 5 статей;
- общий технический лимит статей по периодам:
  - `today` — 25;
  - `3days` — 35;
  - `week` — 45;
- фактически в ИИ отправляется максимум `8` статей.

Логика периода `today`:

Если за сегодня найдено меньше `5` материалов, бот автоматически расширяет поиск до последних 3 дней и добавляет в начало дайджеста пояснение:

```text
За сегодня найдено мало материалов, поэтому я добавил свежие новости за последние 3 дня.
```

Логика режима `По интересам`:

Интересы не являются жестким фильтром. Бот ранжирует новости по совпадению с интересами пользователя. Если совпадений нет, бот не возвращает пустой дайджест, а выбирает самые свежие новости из выбранных источников.

После отбора бот логирует техническую статистику: сколько источников выбрано, сколько источников использовано, сколько статей собрано до фильтрации, сколько осталось после фильтрации по дате, после дедупликации и сколько статей отправлено в ИИ.

## Проверка RSS-источников

Для точечной диагностики одного RSS-источника используется скрипт:

```bash
python scripts/debug_rss_fetch.py rbc_news
```

Скрипт использует тот же RSS-fetcher и те же HTTP headers, что и бот:

- `User-Agent`;
- `Accept`;
- `Accept-Language`;
- `Cache-Control`.

Это нужно, чтобы проверка совпадала с реальным поведением бота, а не с ручным `curl`.

Примеры:

```bash
python scripts/debug_rss_fetch.py rbc_news
python scripts/debug_rss_fetch.py portal_kultura
python scripts/debug_rss_fetch.py pedsovet
```

Можно проверить прямой URL:

```bash
python scripts/debug_rss_fetch.py "https://rssexport.rbc.ru/rbcnews/news/30/full.rss" --source-id rbc_manual
```

Старый скрипт массовой проверки:

```bash
python scripts/validate_sources.py --path app/data/sources.xlsx
```

считается legacy/deprecated и оставлен только для общей проверки всех источников и генерации CSV/XLSX-отчетов.

## Большие дайджесты

Если дайджест не помещается в одно сообщение Telegram, бот больше не предлагает `DOCX/PDF`.

Вместо этого доступны три сценария:

### HTML-страница

- Для дайджеста создается HTML-файл в `app/data/html_digests/`.
- Файлы не удаляются автоматически.
- В таблице `digest_history` сохраняются поля `html_token` и `html_path`.
- Доступ к странице идет по непредсказуемому адресу: `/digest/<token>`.
- Ссылка строится от `PUBLIC_BASE_URL`.

Пример:

```text
http://SERVER_IP:PORT/digest/<random_token>
```

HTML-страница оформляется как адаптивная страница сайта: с аккуратной типографикой, блоком `Очень кратко`, блоком `Подробно`, карточками новостей, кликабельными ссылками и итоговым выводом.

### Отправка частями

Кнопка `📩 Получить частями`:

- разбивает дайджест по блокам новостей;
- старается делить на 2 части, если это безопасно;
- иначе делит на 3 или 4 части;
- не навешивает inline-кнопки на промежуточные сообщения;
- прикрепляет действия дайджеста только к последней части;
- добавляет в начало каждой части префикс `Часть 1/3`, `Часть 2/3` и так далее.

### Укороченная версия

Кнопка `🔁 Перегенерировать короче`:

- не списывает попытку заранее;
- не списывает попытку при ошибке ИИ;
- не списывает попытку при пустом ответе;
- не списывает попытку, если результат все равно слишком длинный.

Если сократить не удалось, бот предлагает открыть HTML-страницу или получить дайджест частями.

### Что больше не используется

- `DOCX`-экспорт;
- `PDF`-экспорт;
- кнопки `Получить DOCX` и `Получить PDF` в UX длинных дайджестов.

Модуль `app/core/documents.py` оставлен как legacy-код и не используется в новом сценарии больших дайджестов.

## История и избранное

Все созданные дайджесты автоматически сохраняются в историю.

В истории отображаются даты созданных дайджестов. Если дайджест добавлен в избранное, рядом с датой отображается звездочка:

```text
21-05-2026 ⭐
20-05-2026
19-05-2026 ⭐
```

Для коротких дайджестов история открывает текст прямо в Telegram.

Для больших дайджестов история не пытается вставить весь длинный текст в сообщение. Вместо этого показывается сервисное сообщение с кнопками:

```text
🌐 Открыть полный дайджест
📩 Получить частями
⭐ В избранное / Убрать из избранного
← Назад
```

HTML-ссылка хранится вместе с записью дайджеста и доступна из истории.

## Обновление и оценка дайджеста

### Проверка новых новостей

Попытка обновления теперь списывается только если:

- найдены новые новости;
- собран новый дайджест.

Если новых материалов нет, пользователь видит сообщение:

```text
Новых новостей пока нет. Попытка обновления не списана.
```

### Оценка дайджеста

После `👍 Полезно` или `👎 Не подходит`:

- оценка сохраняется;
- кнопки оценки удаляются из текущего дайджеста;
- бот отправляет отдельное новое сообщение с полноценным главным меню.

## Расписание рассылок

Пользователь может настроить регулярную отправку дайджестов:

```text
Каждое утро
Каждый вечер
Раз в неделю
```

Для утренней рассылки доступны варианты:

```text
08:00
09:00
10:00
```

Для вечерней рассылки:

```text
18:00
19:00
20:00
```

Для еженедельной рассылки пользователь выбирает день недели и время.

Если часовой пояс еще не выбран, бот предлагает выбрать город с UTC-смещением, например:

```text
Москва UTC+3
Екатеринбург UTC+5
Красноярск UTC+7
Владивосток UTC+10
```

В настройках также можно включить или отключить уведомления без звука.

## Админ-панель

Админ-панель доступна по команде:

```text
/admin
```

Доступ имеет только пользователь, чей Telegram ID указан в переменной окружения:

```env
ADMIN_ID=
```

В админ-панели доступны разделы:

```text
📊 Статистика
🔍 Проверить RSS-источники
♻️ Перезагрузить источники
🧪 Тестовый дайджест
Назад
```

### Статистика

Раздел статистики содержит:

- общее количество пользователей;
- количество созданных дайджестов;
- количество избранных дайджестов;
- количество положительных и отрицательных оценок;
- список пользователей.

Если пользователей больше 8, список отображается с пагинацией.

В карточке пользователя отображаются:

- Telegram ID;
- username;
- имя;
- фамилия;
- количество созданных дайджестов;
- количество избранных дайджестов;
- количество выбранных источников;
- оценки пользователя.

### Проверка RSS-источников

Админ может запустить проверку активных RSS-источников. Бот проверяет, какие ленты доступны, а какие возвращают ошибку или пустой результат.

### Перезагрузка источников

Эта функция заново читает `sources.xlsx` без перезаписи файла.

### Тестовый дайджест

Админ может создать тестовый дайджест по той же логике, что и обычный пользователь:

1. выбрать основу дайджеста;
2. выбрать период;
3. получить результат.

Если тестовый дайджест получается слишком большим, он обрабатывается по той же логике, что и пользовательский: через HTML-страницу или отправку частями.

## ИИ-провайдеры и модель ChatGPT

В настройках бота пользователь может выбрать ИИ-провайдера: `GigaChat` или `ChatGPT`. Это именно выбор провайдера, а не конкретной модели.

Конкретная модель ChatGPT задается администратором через `.env`.

Исключение: нормализация интересов сделана как отдельный дешевый технический шаг и использует короткий запрос к `gpt-5.4-nano`.

В проекте предусмотрены переменные:

```env
OPENAI_API_KEY=
OPENAI_MODEL=gpt-5.4
OPENAI_FALLBACK_MODEL=gpt-5.4-mini
OPENAI_DAILY_TOKEN_LIMIT=200000
OPENAI_BASE_URL=https://api.openai.com/v1
AI_PROVIDER=gigachat
```

Для моделей `gpt-5.*` используется параметр `max_completion_tokens`, потому что эти модели не поддерживают старый параметр `max_tokens`.

Чтобы не упереться в дневной лимит, бот ведет локальный счетчик токенов OpenAI в `logs/openai_usage.json`. Если расход базовой модели достигает порога `OPENAI_DAILY_TOKEN_LIMIT`, до следующего дня новые ChatGPT-запросы автоматически переводятся на `OPENAI_FALLBACK_MODEL`.

Модели ИИ не являются идеальными: они могут ошибаться в фактах, выбирать неидеальные акценты, нарушать формат или возвращать лишний текст. Поэтому в проекте есть fallback-логика, лимиты на входные новости, постобработка HTML и защита от слишком длинных сообщений Telegram.

В тестах проекта на одном и том же наборе RSS-новостей `GigaChat` чаще ошибался при сжатии материалов: мог потерять важные числа из описаний, смешать детали соседних RSS items или неточно обобщить факт. `ChatGPT` на этих же диагностических кейсах показал более стабильный результат, но это не означает стопроцентную точность. Такое поведение связано с ограничениями выбранных моделей и нулевым бюджетом учебного проекта.

Для контроля добавлены диагностические скрипты и подробное LLM-логирование, но полностью исключить фактологические ошибки невозможно. Если доступен API-ключ и хватает лимита, для более стабильного качества рекомендуется использовать `ChatGPT`-провайдер. В любом режиме итоговый дайджест остается автоматической ИИ-сводкой, а не редакторски выверенным материалом.

## Запуск через proxy

По умолчанию бот запускается без proxy:

```env
BOT_USE_PROXY=false
BOT_PROXY_URL=
```

Proxy-режим добавлен для серверов, где прямой доступ к Telegram Bot API ограничен, нестабилен или сильно замедлен. Бот поддерживает HTTP и SOCKS5 proxy.

Примеры:

```env
BOT_USE_PROXY=true
BOT_PROXY_URL=socks5://login:password@host:port
BOT_PROXY_URL=socks5://host:port
BOT_PROXY_URL=http://login:password@host:port
BOT_PROXY_URL=http://host:port
```

Если `BOT_USE_PROXY=false` или `BOT_PROXY_URL` пустой, бот создает обычную сессию без proxy. В логах при старте будет:

```text
Bot started without proxy
```

Если proxy включен, пароль в логах не показывается:

```text
Bot started with proxy: socks5://***
```

## Watchdog для VPS

В проекте предусмотрен файл:

```text
watchdog.py
```

Он нужен для запуска и мониторинга бота на сервере.

Watchdog выполняет следующие задачи:

- запускает бота;
- пишет события и ошибки в лог;
- перезапускает бота, если процесс завершился с ошибкой;
- корректно завершает дочерний процесс при остановке.

Логи сохраняются в папку:

```text
logs/
```

Для запуска с автоматическим перезапуском:

```bash
python watchdog.py
```

Этот способ удобен для VPS, потому что бот будет перезапущен, если процесс неожиданно завершится.
