# ИнфоПульс

Telegram-бот для персональных новостных дайджестов из RSS-источников.

## Что умеет бот

- Собирает дайджест из выбранных RSS-лент.
- Поддерживает два режима чтения:
  - `📡 По источникам` — собирает новости из выбранных пользователем RSS-источников.
  - `🎯 По интересам` — использует те же выбранные RSS-источники, но поднимает выше новости, которые ближе к интересам пользователя.
- Помогает указать интересы и подобрать источники через ИИ.
- Хранит историю дайджестов, избранное и оценку полезности.
- Поддерживает плановые рассылки.
- Работает с `GigaChat` и `ChatGPT` как с LLM-провайдерами.

## Единый onboarding и главное меню

Во всех сценариях главное меню показывает один и тот же текст:

```text
👋 ИнфоПульс помогает собрать короткий новостной дайджест из RSS-источников.

Можно читать новости двумя способами:

📡 По источникам — бот собирает дайджест из выбранных вами RSS-лент.

🎯 По интересам — бот использует выбранные RSS-ленты и выше ставит новости, которые ближе к вашим темам.

Как получить дайджест:
1. Добавьте или измените интересы.
2. Подберите или измените источники через ИИ или вручную.
3. Нажмите «Получить дайджест сейчас».
4. Выберите режим и период.

Интересы не заменяют источники: они помогают точнее отсортировать новости внутри выбранных лент.
```

Этот текст используется в `/start`, при возврате в меню через callback и после оценки дайджеста.

## Как теперь выглядит дайджест

Telegram-дайджест формируется только в HTML-совместимом формате:

```html
<b>📰 Дайджест за сегодня (22.05.2026)</b>

<b>Очень кратко</b>
<blockquote>...</blockquote>

<b>Подробно</b>

<b>1. Заголовок новости</b>
<b>Кратко:</b> ...
<b>Почему важно:</b> ...
Источник: <a href="URL">Название источника</a>

<b>Итог</b>
<blockquote>...</blockquote>
```

Что изменено относительно прошлой версии:

- слоган полностью убран;
- заголовок `Новости` заменен на `Подробно`;
- `Кратко:` и `Почему важно:` теперь всегда выделяются жирным;
- используется только Telegram-compatible HTML, без Markdown.

## Сценарий пользователя

### 1. Интересы

Пользователь может:

- сохранить интересы обычным текстом;
- получить нормализованные ключевые слова;
- вручную отредактировать эти слова.

### 2. Источники

Пользователь может:

- подобрать источники по интересам через ИИ;
- выбрать источники вручную по категориям;
- увидеть рекомендацию по объему: оптимально выбирать `3–7` источников.

Если источников выбрано много, перед генерацией бот предупреждает, что дайджест может получиться длинным.

### 3. Линейный flow “интересы → источники → дайджест”

После `Добавить все` в рекомендованных источниках бот больше не уводит пользователя в “Мои подписки”.

Теперь показывается экран:

- `📰 Получить дайджест по интересам`
- `📡 Изменить источники`
- `🏠 Главное меню`

Кнопка `📰 Получить дайджест по интересам` сразу переводит к выбору периода для режима `interests`.

## Большие дайджесты

Если дайджест не помещается в одно сообщение Telegram, бот больше не предлагает `DOCX/PDF`.

Вместо этого доступны три сценария:

### HTML-страница

- Для дайджеста создается HTML-файл в `app/data/html_digests/`.
- Файлы не удаляются автоматически.
- В таблице `digest_history` сохраняются поля `html_token` и `html_path`.
- Доступ к странице идет по непредсказуемому адресу: `/digest/<token>`.
- Ссылка строится от `PUBLIC_BASE_URL`.

Пример:

```text
http://SERVER_IP:PORT/digest/<random_token>
```

### Отправка частями

Кнопка `📩 Получить частями`:

- разбивает дайджест по блокам новостей;
- старается делить на 2 части, если это безопасно;
- иначе делит на 3 или 4 части;
- не навешивает inline-кнопки на промежуточные сообщения;
- прикрепляет действия дайджеста только к последней части;
- добавляет в начало каждой части префикс `Часть 1/3`, `Часть 2/3` и так далее.

### Укороченная версия

Кнопка `🔁 Перегенерировать короче` теперь:

- не списывает попытку заранее;
- не списывает попытку при ошибке ИИ;
- не списывает попытку при пустом ответе;
- не списывает попытку, если результат все равно слишком длинный.

Если сократить не удалось, бот предлагает открыть HTML-страницу или получить дайджест частями.

## История больших дайджестов

История продолжает работать:

- короткие дайджесты открываются текстом прямо в Telegram;
- длинные дайджесты открываются через сервисное сообщение с кнопками:
  - `🌐 Открыть полный дайджест`
  - `📩 Получить частями`
  - `⭐ В избранное / Убрать из избранного`
  - `← Назад`

HTML-ссылка хранится вместе с записью дайджеста и доступна из истории.

## Обновление и оценка дайджеста

### Refresh

Попытка обновления теперь списывается только если:

- найдены новые новости;
- собран новый дайджест.

Если новых материалов нет, пользователь видит сообщение:

```text
Новых новостей пока нет. Попытка обновления не списана.
```

### Feedback

После `👍 Полезно` или `👎 Не подходит`:

- оценка сохраняется;
- кнопки оценки удаляются из текущего дайджеста;
- бот отправляет отдельное новое сообщение с полноценным главным меню.

## HTML-страница дайджеста

В проекте добавлен простой встроенный HTTP-сервер на `aiohttp`, который запускается вместе с ботом и обслуживает маршрут:

```text
/digest/{token}
```

Страница:

- адаптивна для телефона;
- показывает `Очень кратко`, `Подробно` и `Итог`;
- рендерит новости карточками;
- сохраняет кликабельные ссылки на источники.

## Конфигурация

Основные переменные окружения:

```env
BOT_TOKEN=
AI_PROVIDER=gigachat
OPENAI_API_KEY=
OPENAI_MODEL=gpt-5.4
OPENAI_FALLBACK_MODEL=gpt-5.4-mini
OPENAI_BASE_URL=https://api.openai.com/v1
PUBLIC_BASE_URL=http://127.0.0.1:8080
DATABASE_URL=sqlite+aiosqlite:///./bot.db
ADMIN_ID=
LOG_LEVEL=INFO
```

### PUBLIC_BASE_URL

`PUBLIC_BASE_URL` нужен для публичной ссылки на HTML-страницы дайджестов.

Примеры:

- `http://127.0.0.1:8080`
- `http://SERVER_IP:8080`
- `https://news.example.com`

## Структура проекта

```text
app/
  bot/
    handlers/      # Telegram callbacks и сценарии UX
    keyboards/     # inline-клавиатуры
    main.py        # запуск бота
  core/
    digest.py              # сборка и обновление дайджеста
    digest_delivery.py     # длинные дайджесты, HTML-страницы, разбиение на части
    gigachat_client.py     # работа с GigaChat / ChatGPT
    scheduler.py           # плановые рассылки
  db/
    models.py       # SQLAlchemy-модели
    queries.py      # запросы к SQLite
    database.py     # init_db и миграции
  web/
    server.py       # HTTP route /digest/{token}
  data/
    html_digests/   # постоянный архив HTML-страниц
```

## Что больше не используется

- `DOCX`-экспорт;
- `PDF`-экспорт;
- кнопки `Получить DOCX` и `Получить PDF` в UX длинных дайджестов.

Модуль `app/core/documents.py` оставлен в репозитории как неиспользуемый legacy-код, чтобы не тянуть лишний рефакторинг в текущем hotfix-наборе.

## Проверка после изменений

Для быстрой локальной проверки полезны:

```bash
python -m compileall app
```

и запуск бота в обычном режиме, чтобы проверить:

- единый onboarding;
- режимы `По источникам` и `По интересам`;
- длинный дайджест через HTML/части;
- историю длинных дайджестов;
- refresh / shorten / feedback сценарии.
