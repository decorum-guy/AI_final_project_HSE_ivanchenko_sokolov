## Описание проекта

**ИнфоПульс** — Telegram-бот для персонализированных новостных дайджестов.

Бот собирает материалы из RSS-источников, помогает пользователю выбрать интересующие темы и источники, формирует краткие дайджесты с помощью ИИ и сохраняет историю ранее созданных подборок.

Важно: проект использует доступные учебные ресурсы и бесплатный/бюджетный режим работы с ИИ. В частности, при использовании GigaChat Lite качество форматирования и фактическая точность могут быть хуже, чем у более дорогих моделей уровня Pro/Max. Невозможно заранее заложить обработку абсолютно всех ошибок генеративной модели: ИИ может ошибиться в фактах, акцентах, структуре или HTML-разметке. В проекте добавлены проверки, постобработка, fallback-сценарии и лимиты, но стопроцентно идеальный контроль содержимого невозможен.

Проект ориентирован на автоматизацию коммуникационного процесса: пользователь не просматривает десятки сайтов вручную, а получает сжатую и структурированную новостную сводку по своим интересам.

## Основные возможности

- Получение новостного дайджеста по интересам пользователя.
- Получение дайджеста по вручную выбранным RSS-источникам.
- ИИ-подбор RSS-источников по интересам пользователя.
- Ручное исключение отдельных источников из ИИ-рекомендаций перед добавлением.
- HTML-оформление дайджеста для Telegram: жирные заголовки, цитаты, кликабельные ссылки и короткий слоган.
- Выбор периода дайджеста:
  - за сегодня;
  - за последние 3 дня;
  - за неделю.
- Ручной выбор источников через меню:
  - категории;
  - источники внутри категории;
  - отображение выбранных источников через `✅` и `☐`.
- Хранение истории дайджестов.
- Добавление дайджестов в избранное.
- Оценка дайджеста:
  - `👍 Полезно`;
  - `👎 Не подходит`.
- Проверка новых новостей после генерации дайджеста.
- Настройка регулярных рассылок:
  - каждое утро;
  - каждый вечер;
  - раз в неделю.
- Выбор часового пояса через город и UTC-смещение.
- Настройка уведомлений без звука.
- Админ-панель.
- Watchdog-скрипт для запуска и мониторинга бота на VPS.

## Логика работы бота

Полная карта пользовательской навигации вынесена в [BOT_FLOW.md](BOT_FLOW.md). Там описано главное меню, все основные кнопки, переходы назад, сценарии дайджеста, интересов, источников, истории, расписания, настроек и админ-панели.

### Получение дайджеста

Сценарий начинается из главного меню по кнопке:

```text
📰 Получить дайджест
```

После этого бот предлагает выбрать основу дайджеста:

```text
🎯 По моим интересам
📡 По выбранным источникам
```

Режимы отличаются так:

- `🎯 По моим интересам` — бот берет выбранные пользователем источники, но дополнительно ранжирует новости по `interests_text`. Выше попадают новости, которые ближе к указанным темам.
- `📡 По выбранным источникам` — бот берет выбранные источники и собирает свежие новости без дополнительной персонализации по интересам.

Важно: ИИ-подбор источников и дайджест по интересам — разные функции. ИИ-подбор помогает выбрать подходящие RSS-подписки на основе интересов, а режим «По моим интересам» персонально сортирует новости внутри уже выбранных источников.

Затем пользователь выбирает период:

```text
За сегодня
За последние 3 дня
За неделю
```

После выбора периода бот собирает новости из RSS-источников, формирует HTML-дайджест для Telegram и автоматически сохраняет его в историю.

Дайджест содержит:

- жирный заголовок;
- короткое описание в цитате;
- строку `Слоган дайджеста:` и сам слоган;
- новости с кратким объяснением и кликабельными ссылками;
- итоговый вывод.

### Как работает ИИ-подбор источников

ИИ-подбор источников запускается из раздела `🎯 Мои интересы`. Пользователь пишет интересы обычным текстом, например:

```text
люблю технологии, игры и театр
```

После этого бот читает активные источники из `sources.xlsx` и передает модели список доступных RSS-источников: `source_id`, название, категорию и описание. Модель выбирает только источники из этого списка и возвращает рекомендации. Если ИИ недоступен или вернул некорректный JSON, бот использует fallback-подбор по ключевым словам.

Важно: ИИ-подбор источников не генерирует сам дайджест. Он только помогает сформировать список подписок. Сам дайджест потом строится по уже выбранным источникам.

### Чем отличаются режимы дайджеста

`📡 По выбранным источникам` — бот берет выбранные RSS-источники и собирает свежие новости за выбранный период. Интересы пользователя в этом режиме не влияют на порядок материалов.

`🎯 По моим интересам` — бот тоже берет выбранные RSS-источники, но дополнительно использует текст интересов для ранжирования новостей. То есть источники остаются теми же, а новости внутри них сортируются так, чтобы выше попадали материалы ближе к интересам пользователя.

Пример: если в интересах указано `технологии, игры и театр`, а вручную выбраны `3DNews Железо`, `CNews` и `Хакер`, то режим по интересам не пойдет искать другие источники. Он соберет новости именно из этих трех источников, но выше поставит материалы, которые ближе к технологиям, играм и похожим темам.

### ИИ-провайдеры и модель ChatGPT

В настройках бота пользователь может выбрать ИИ-провайдера: `GigaChat` или `ChatGPT`. Это именно выбор провайдера, а не конкретной модели.

Конкретная модель ChatGPT задается администратором через `.env`. В проекте подключен режим data sharing, поэтому доступны бесплатные лимиты: до 250 000 токенов в сутки для `gpt-5.4` и до 2 500 000 токенов в сутки для `gpt-5.4-mini`. Есть и другие модели, но для MVP выбраны самые сильные варианты в этих двух классах.

Основная модель — `gpt-5.4`. Чтобы не упереться в суточный лимит, бот ведет локальный счетчик токенов OpenAI в `logs/openai_usage.json`. Если расход базовой модели достигает порога `OPENAI_DAILY_TOKEN_LIMIT`, до следующего дня новые ChatGPT-запросы автоматически переводятся на `OPENAI_FALLBACK_MODEL`, сейчас это `gpt-5.4-mini`.

Модели ИИ не являются идеальными: они могут ошибаться в фактах, выбирать неидеальные акценты, нарушать формат или возвращать лишний текст. Поэтому в проекте есть fallback-логика, лимиты на входные новости, постобработка HTML и защита от слишком длинных сообщений Telegram.

## Источники новостей

Источники хранятся в файле:

```text
app/data/sources.xlsx
```

В книге два листа:

- `Sheet1` - основной лист с RSS-источниками, который читает бот;
- `category_summary` - сводка с количеством источников по категориям для быстрой проверки наполнения.

Структура таблицы:

| Поле | Описание |
|---|---|
| `source_id` | уникальный идентификатор источника |
| `title` | название источника |
| `category` | категория источника |
| `description` | краткое описание |
| `rss_url` | ссылка на RSS-ленту |
| `is_active` | активен ли источник |

Пример строки:

| source_id | title | category | description | rss_url | is_active |
|---|---|---|---|---|---|
| `habr_articles` | Хабр | IT | Разработка, IT, технологии и инженерные статьи | `https://habr.com/ru/rss/articles/` | `true` |

Важно: файл `sources.xlsx` используется как основной список источников. Если файл уже существует, его не нужно пересоздавать или перезаписывать.

## Проверка RSS-источников

Для диагностики RSS-лент в проекте есть скрипт:

```bash
python scripts/validate_sources.py --path app/data/sources.xlsx
```

Скрипт читает `sources.xlsx` через `pandas/openpyxl`, не изменяет исходный Excel-файл и сохраняет отчеты в папку `reports/`.

Проверка использует тот же RSS-fetcher, что и бот:

- загрузка RSS через `aiohttp`;
- единые HTTP headers;
- полный `response.read()` перед анализом;
- `feedparser.parse()` по `bytes`;
- одинаковая логика статусов `OK`, `WARNING`, `ERROR`.

Если источник имеет `bozo=True`, но содержит `entries`, он считается рабочим с предупреждением. Если новостей нет или возникла HTTP/fetch-ошибка, источник пропускается и не ломает дайджест.

Примеры:

```bash
python scripts/validate_sources.py --path app/data/sources.xlsx
python scripts/validate_sources.py --path app/data/sources.xlsx --timeout 15 --concurrency 6
python scripts/validate_sources.py --path app/data/sources.xlsx --include-inactive
```

## История и избранное

Все созданные дайджесты автоматически сохраняются в историю.

В истории отображаются даты созданных дайджестов. Если дайджест добавлен в избранное, рядом с датой отображается звездочка:

```text
21-05-2026 ⭐
20-05-2026
19-05-2026 ⭐
```

При открытии дайджеста из истории бот редактирует текущее сообщение, а не создает новое. Это делает интерфейс чище и удобнее.

## Расписание рассылок

Пользователь может настроить регулярную отправку дайджестов:

```text
Каждое утро
Каждый вечер
Раз в неделю
```

Для утренней рассылки доступны варианты:

```text
08:00
09:00
10:00
```

Для вечерней рассылки:

```text
18:00
19:00
20:00
```

Для еженедельной рассылки пользователь выбирает день недели и время.

Если часовой пояс еще не выбран, бот предлагает выбрать город с UTC-смещением, например:

```text
Москва UTC+3
Екатеринбург UTC+5
Красноярск UTC+7
Владивосток UTC+10
```

Админ-панель доступна по команде:

```text
/admin
```

Доступ имеет только пользователь, чей Telegram ID указан в переменной окружения:

```env
ADMIN_ID=
```

В админ-панели доступны разделы:

```text
📊 Статистика
🔍 Проверить RSS-источники
♻️ Перезагрузить источники
🧪 Тестовый дайджест
Назад
```

### Статистика

Раздел статистики содержит:

- общее количество пользователей;
- количество созданных дайджестов;
- количество избранных дайджестов;
- количество положительных и отрицательных оценок;
- список пользователей.

Если пользователей больше 8, список отображается с пагинацией.

В карточке пользователя отображаются:

- Telegram ID;
- username;
- имя;
- фамилия;
- количество созданных дайджестов;
- количество избранных дайджестов;
- количество выбранных источников;
- оценки пользователя.

### Проверка RSS-источников

Админ может запустить проверку активных RSS-источников. Бот проверяет, какие ленты доступны, а какие возвращают ошибку или пустой результат.

### Перезагрузка источников

Эта функция заново читает `sources.xlsx` без перезаписи файла.

### Тестовый дайджест

Админ может создать тестовый дайджест по той же логике, что и обычный пользователь:

1. выбрать основу дайджеста;
2. выбрать период;
3. получить результат.

## Watchdog для VPS

В проекте предусмотрен файл:

```text
watchdog.py
```

Он нужен для запуска и мониторинга бота на сервере.

Watchdog выполняет следующие задачи:

- запускает бота;
- пишет события и ошибки в лог;
- перезапускает бота, если процесс завершился с ошибкой;
- корректно завершает дочерний процесс при остановке.

Логи сохраняются в папку:

```text
logs/
```

## Запуск через proxy

По умолчанию бот запускается без proxy:

```env
BOT_USE_PROXY=false
BOT_PROXY_URL=
```

Proxy-режим добавлен для серверов, где прямой доступ к Telegram Bot API ограничен, нестабилен или сильно замедлен. Бот поддерживает HTTP и SOCKS5 proxy.

Примеры:

```env
BOT_USE_PROXY=true
BOT_PROXY_URL=socks5://login:password@host:port
BOT_PROXY_URL=socks5://host:port
BOT_PROXY_URL=http://login:password@host:port
BOT_PROXY_URL=http://host:port
```

Если `BOT_USE_PROXY=false` или `BOT_PROXY_URL` пустой, бот создает обычную сессию без proxy. В логах при старте будет:

```text
Bot started without proxy
```

Если proxy включен, пароль в логах не показывается:

```text
Bot started with proxy: socks5://***
```

## Проверка подключения к GigaChat

Для быстрой проверки ключа GigaChat есть отдельный скрипт:

```bash
python scripts/test_gigachat.py
```

Скрипт читает `GIGACHAT_CREDENTIALS` из `.env`, отправляет простой тестовый запрос в модель и печатает короткий ответ. Ключ в выводе не раскрывается полностью.

Можно передать свой prompt или модель:

```bash
python scripts/test_gigachat.py --prompt "Ответь коротко, что подключение работает"
python scripts/test_gigachat.py --model GigaChat
```

## Проверка ChatGPT-моделей

Для проверки, что `OPENAI_MODEL` и `OPENAI_FALLBACK_MODEL` реально доступны и тарифицируются как ожидается, есть микро-тест:

```bash
python scripts/test_openai_models.py
```

Скрипт берет `OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_FALLBACK_MODEL` и `OPENAI_BASE_URL` из `.env`, делает по одному короткому запросу к каждой модели и печатает ответы. Его удобно запускать перед демонстрацией или после изменения модели в `.env`.

Если переменная `GIGACHAT_CREDENTIALS` пустая или запрос не прошел, скрипт выведет понятную ошибку.

### Полезные команды на VPS

Перейти в папку проекта:

```bash
cd /home/codex/apps/AI_final_project_HSE_ivanchenko_sokolov
```

Активировать виртуальное окружение:

```bash
source .venv/bin/activate
```

Запустить бота без watchdog для ручной проверки:

```bash
python -m app.bot.main
```

Запустить через watchdog:

```bash
python watchdog.py
```

Запустить watchdog в фоне без `tmux`:

```bash
setsid -f .venv/bin/python watchdog.py > logs/watchdog.out 2>&1 < /dev/null
```

Проверить процессы watchdog и бота:

```bash
pgrep -af 'watchdog.py|app.bot.main'
```

Остановить watchdog и бота:

```bash
kill -TERM <watchdog_pid> <bot_pid>
```

Если известны PID из `pgrep`, пример:

```bash
kill -TERM 12345 12346
```

Очистить логи:

```bash
find logs -maxdepth 1 -type f -exec truncate -s 0 {} \;
```

Смотреть логи watchdog:

```bash
tail -f logs/watchdog.log
```

Смотреть основной лог бота:

```bash
tail -f logs/bot.log
```

Смотреть только ошибки бота:

```bash
tail -f logs/bot-errors.log
```

Смотреть подробный debug-лог:

```bash
tail -f logs/bot-debug.log
```

## Проверка работоспособности

После запуска рекомендуется проверить:

1. `/start` открывает главное меню.
2. Работает получение дайджеста.
3. Работает ручной выбор источников.
4. Источники отображаются по категориям.
5. Выбранные источники отмечаются через `✅`.
6. История дайджестов открывается.
7. Избранное переключается.
8. Оценки сохраняются.
9. Расписание сохраняется.
10. Настройки часового пояса работают.
11. Админ-панель открывается только для `ADMIN_ID`.
12. Watchdog перезапускает бота при падении процесса.

## Краткое описание пользовательского сценария

1. Пользователь запускает бота.
2. Выбирает интересы или RSS-источники.
3. Запрашивает дайджест за нужный период.
4. Получает краткую сводку новостей.
5. Может добавить дайджест в избранное.
6. Может оценить качество подборки.
7. Может вернуться к прошлым дайджестам через историю.
8. Может настроить регулярную рассылку.

## Назначение проекта
